# 客户端文档维护策略

客户端会自行更新，界面和参数随时可能变化。这一页说明我们如何让接入文档跟上变化，以及看到过期内容时怎么反馈。

## 最近核验

每篇客户端接入文档的顶部标有「最近核验」日期，表示在那一天有人按文档在真实客户端上完整走了一遍，确认步骤和截图与实际一致。

页脚的「最后更新于」是另一回事，它来自 Git 提交时间，改一个错别字也会刷新。判断内容是否跟得上客户端版本，看「最近核验」。

## 核验周期

目标是 30 天内至少核验一次。每次核验检查：

| 检查项     | 说明                             |
| ---------- | -------------------------------- |
| 安装方式   | 命令、包名、下载入口是否仍然有效 |
| 配置项名称 | 客户端改版后设置项常被改名或移位 |
| 截图       | 与当前界面是否一致               |
| 验证步骤   | 文档给出的验证命令能否正常返回   |

客户端发布大版本时会提前核验，不等周期到期。

## 覆盖范围

策略适用于 [Agents](/docs/agents/claude-code) 和 [ChatBot](/docs/chatbot/cherry-studio) 两类客户端接入文档。

计费、错误码、API 端点这类文档不标核验日期，它们跟随 TokenFlux 自身变更，改动时同步更新。

## 发现内容过期

文档与实际不符时，用以下任一方式反馈：

- 页面底部的「在 GitHub 上编辑此页」直接提交修改
- 在 [仓库](https://github.com/TokenFlux/TokenDocs) 提 issue，注明客户端名称与版本
- 按 [排障](/docs/troubleshooting#怎么反馈) 的模板反馈

请附上客户端版本号。同一份文档在不同版本下的表现可能完全不同。
