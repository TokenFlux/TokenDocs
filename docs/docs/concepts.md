# 核心概念

分组、号池、推理积分这些词会在文档里反复出现。这一页集中说明它们是什么，以及一个请求可能在哪个环节被拒绝。

## 术语

| 术语 | 含义 |
| --- | --- |
| 推理积分 `🍥` | 计费单位，账户余额和订阅额度都用它计量 |
| 分组 | 一批模型的集合，带有自己的倍率和容量 |
| 倍率 | 分组作用在模型原价上的系数 |
| 号池 | 分组背后的上游账号 |
| 作用域 | 密钥归个人还是团队，决定由谁付款 |
| 复合 Key | 一个 Key 绑定多个分组，用前缀区分 |

## 分组

分组决定三件事：能用哪些模型、按什么价格计费、请求发给哪批上游账号。

创建 API Key 时必须选一个分组，下拉菜单里会显示该分组的倍率和当前容量。普通 Key 只能绑一个分组，需要同时使用多个分组时用[复合 Key](/docs/tokenflux/composite-key)。

倍率作用在模型原价上，但 [模型广场](https://tokenflux.dev/models) 显示的价格已经含了倍率，那就是最终扣费价格，不需要再乘一次。

::: tip 分组不是套餐
分组是 API Key 的属性，订阅套餐（Lite / Plus / Pro 等）是账户的属性，两者互不相关。
:::

### 需要留意的分组

| 分组 | 说明 |
| --- | --- |
| `ChatGPT Pro` | 仅适用于 Codex App 和 Codex CLI，其他接入方式请勿选择 |
| 数据共享 | 以脱敏后的请求和响应数据换取更低价格，详见 [计费说明](/docs/tokenflux/billing) |

涉及数据共享的分组会在模型广场、购买页和分组说明中明确标出，不会以默认选项或隐藏选项的方式开启。

## 号池

号池是分组背后的上游账号。`Pro` 号池包含 Pro 模型，服务压力较大时访问优先级可能更高；除此之外与 `Plus` 号池没有区别。

账号类型会影响部分功能是否可用。[Fast 模式](/docs/tokenflux/fast-mode) 的强制开启就要求命中 OpenAI 或 Anthropic 平台的账号，且 Anthropic 账号必须使用 API Key 凭据——命中 Bedrock、Vertex 或 OAuth 凭据时会静默跳过。

## API Key

Key 有两个互相独立的属性。

**作用域**决定谁付款，创建后不能更改。

| 作用域 | 付款方 | 可选分组来自 |
| --- | --- | --- |
| 个人 | 本人 | 本人的分组权益 |
| 团队 | 团队所有者 | 所有者的分组权益 |

**类型**决定怎么指定分组。

| 类型 | 绑定分组 | 调用写法 |
| --- | --- | --- |
| 普通 | 1 个 | `模型 ID` |
| [复合](/docs/tokenflux/composite-key) | 最多 20 个 | `前缀/模型 ID` |

## 费用怎么算

单次请求分输入、输出、缓存三部分计算，单价取本次请求实际命中的分组。复合 Key 按前缀命中的那个分组算。

扣费顺序是先订阅后余额：系统优先消耗即将到期的订阅额度，没有可用订阅时扣账户余额。

[Fast 模式](/docs/tokenflux/fast-mode) 走上游的高优先级通道，费用约为常规的 2 倍。

## 请求可能在哪里被拒绝

排查失败请求时按这个顺序核对：

| 环节 | 检查什么 |
| --- | --- |
| 密钥 | 是否存在、被禁用、已过期；团队密钥还要求成员与所有者账号都正常，且团队未暂停 |
| 分组解析 | 复合 Key 的模型 ID 必须带前缀，且前缀在映射内，否则返回 `COMPOSITE_KEY_*` |
| 模型权限 | 模型是否属于该分组 |
| 接口支持 | 复合 Key 不支持 WebSocket / Realtime 类接口 |
| 额度 | 账户余额、订阅额度、团队成员的日 / 周 / 月限额，任一不足都会被拒 |
| 上游 | 到这一步请求才真正发给模型服务商 |

另外，TokenFlux 不提供 embedding 模型。
