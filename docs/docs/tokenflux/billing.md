# 计费说明

TokenFlux 以 `🍥`（推理积分）为计费单位。**[模型广场](https://tokenflux.dev/models) 显示的价格即为最终计费价格**。

## 价格如何计算

Token 计费模型按输入、输出和缓存用量分别计费。读取价格时同时确认单位与适用的上下文区间。图片等其他计费方式按对应模型的价格说明计算。

### 分组倍率

不同的 API Key 分组可能有不同的倍率。分组倍率基于模型原价计算，模型广场显示的价格已包含倍率调整，即为实际支付的价格。

分组之间的倍率与客户端限制各不相同。选择前请查看 [核心概念](/docs/concepts#需要留意的分组) 与模型广场中的分组说明。

分组是 API Key 的属性，与下方的订阅套餐（Lite / Plus / Pro 等）无关，两者名称相近但不是一回事。

**示例**

以下为假设计价，不代表某个模型的当前报价，单位均为推理积分 / 1M token：

| 项目 | 原价 | 分组倍率 | 最终单价 |
| ---- | ---- | -------- | -------- |
| 输入 | 2.5  | 1.3      | 3.25     |
| 输出 | 15   | 1.3      | 19.5     |

假设一次请求有 10,000 个输入 token、2,000 个输出 token，没有缓存用量，也未使用 Fast 模式，且全部落在上述价格区间：

```text
输入费用 = 10,000 / 1,000,000 × 3.25 = 0.0325 推理积分
输出费用 = 2,000 / 1,000,000 × 19.5 = 0.039 推理积分
合计 = 0.0715 推理积分
```

实际计算使用 [模型广场](https://tokenflux.dev/models) 已含倍率的最终单价。涉及缓存时，先确认对应协议的输入统计是否包含缓存 token，以及缓存读取、写入的计价项，避免将重叠用量重复相加。实际扣费以 [使用记录](https://tokenflux.dev/usage) 为准。

推理积分不等于人民币金额。购买时在 [充值/订阅页面](https://tokenflux.dev/purchase) 核对实付金额与获得的额度，手续费见下文。

## 购买方式

两种方式都在 [充值/订阅页面](https://tokenflux.dev/purchase) 购买。

### 订阅

通常更便宜，有效期 30 天。共八档，从低到高为 `Lite`、`Lite+`、`Plus`、`Plus+`、`Pro`、`Pro+`、`Max`、`Max+`。各档的日限额、月限额和价格在充值页面查看。

重复购买同一个订阅不会并行新增一份，而是延长时间，后一次在上一个订阅失效后生效。

套餐额度使用完毕后，可在套餐页面自主操作撤销，无需联系管理员；撤销后若账户中有后续套餐，将自动按顺序衔接生效。

可同时开通多个不同套餐。扣费时优先消耗即将到期的套餐额度，没有可用套餐时扣除账户余额。

### 按量

按实际使用量计费，无时间限制。

## 支付与手续费

充值通过 Stripe 处理，原支付宝等渠道已全部迁移。

每笔交易收取 **2.7 元固定手续费**，浮动手续费（交易总额的 2.2%）已免除。固定费用不随金额变化，单次充值金额越高，分摊到每笔的成本越低。

## 套餐名称对照

::: details 曾用名与现用名
套餐名称已统一调整，仅涉及名称，价格、额度、权益和已开通的服务都不受影响。已购买的套餐自动显示为新名称。

| 原名称     | 新名称 |
| ---------- | ------ |
| Basic      | Lite   |
| Standard   | Lite+  |
| Pro        | Plus   |
| Max        | Plus+  |
| Ultra      | Pro    |
| Elite      | Pro+   |
| Enterprise | Max    |
| Ultimate   | Max+   |

:::
